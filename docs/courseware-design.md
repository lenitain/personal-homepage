# 课件设计基准（Design Note）

> 内部文档：给作者（以及后续的 coding agent）看的结构基准，**不属于 `content/`**。
>
> 和另外两份文件的分工：
>
> | 文件 | 管什么 |
> | --- | --- |
> | `docs/content-writing.md` | 单篇/单页怎么写：从高处切入、先接反问、短条目 |
> | **本文** | **一段内容该不该存在、该给数据还是该给实验** |
> | `docs/labs/resident-browser/README.md` | 实验脚本怎么跑、环境要求 |

## 一、判据

读者是**操作系统的使用者**，不是它的管理者。他的模型来自任务管理器、资源管理器、
「关掉终端程序就没了」这类日常经验 —— 够用，但方向和真实机制**系统性错位**。

判断一段内容去留，只问一句：

> **他不做这件事，会不会做出不同的工程决定？**

会 → 必须教，而且要教到能落成决定。
不会 → 一句话带过，或者删掉。

**数字只是因为某个决定需要它才出现，不能反过来。** 一个数有多大、他猜不猜得中，
都不是理由 —— 这门课的目的不是让人猜中，是让人换一种做法。

所以正文的组织单位是**决定**，不是知识点：

```
他本来会怎么做  →  为什么那样不行  →  该怎么做  →  撑住它的那条事实
```

## 二、五个决定点

这门课的全部内容都服务这五个决定。新增任何一段内容之前，先回答「它服务哪一个」。

### ① 启动慢 → 别每次都启动它

- **本来会怎么做**：想办法让 qutebrowser 启动快一点。
- **为什么不行**：那一秒多发生在「它知道你要打开什么」之前，跟页面无关 ——
  对着启动路径优化没有着力点。
- **该怎么做**：把那段恒定的开销保温，让进程活着。
- **撑住它的事实**：启动时间线上的两段（Python 段 / Qt 段），
  以及用 `-R about:blank` 也能量出同样的时间。
- **需要给的量**：时间线的两个数字。
- **只需要一句话的**：常驻的内存底价。它是「值不值得」的阈值输入，
  不是惊喜；答案本来就落在「有没有可切的前言」上。
- **词汇（不是决定）**：`fork`/`execve` 两步、重定向发生在两步之间、shebang。
  这些是后面每一句话的用词，一句话讲清就走，不必给「演示」的仪式感。
- **现有实验**：`13-qutebrowser-checkup.sh`（时间线）；`01`/`02`/`03`（词汇）。

### ② 常驻了 → 生命周期交给 pid 1，不要自己写监督

- **本来会怎么做**：写个脚本管着它，死了重启，退出时收拾干净。
- **为什么不行**：那是在重写 pid 1。而且 namespace 这类**隔离**原语看着像答案，
  实际不负责生命周期（代价还很贵：user namespace 会把身份改掉）。
- **该怎么做**：注册成 systemd service —— 保证来自
  「cgroup 把一组进程圈起来」+「有人指定了谁是主进程」，两者缺一不可。
- **撑住它的事实**：
  1. 父进程退出之后，子进程会被 pid 1 接管（**前提，现在缺**）
  2. 只有 cgroup、没有 MainPID 的 scope 不负责释放；service 负责
  3. 隔离 ≠ 分组：两套正交的机制，用错的那套会引出输入法消失这类代价
- **需要给的量**：三种启动方式杀掉主进程之后子进程还在不在。
- **现有实验**：`11-cgroup-vs-mainpid.sh`；`10-namespace-failure-modes.sh`；
  `14-identity-channels.sh`（代价有多具体）。

### ③ 想让常驻实例更快 → 数据分层，而不是全塞进 RAM

- **本来会怎么做**：把 profile、缓存都搬进内存（tmpfs），读起来快。
- **为什么不行**：搬进内存的那部分是**钉死的**，内核回收不掉；
  而留在磁盘上的东西，内核本来就会拿它当缓存使 —— 全塞进去等于白付一笔永久租金。
- **该怎么做**：能重做的留在磁盘；只有这次会话写下的增量进内存（overlayfs 的 copy-up）。
- **撑住它的事实**：
  1. 读过的文件第二遍不读盘（page cache）（**前提，现在缺**）
  2. tmpfs 页没有后备存储，内存紧张时动不了；文件后备页可以被丢掉（**前提，现在缺**）
  3. 关窗之后进程数不会归零 —— 那部分是买来的东西，不是 bug
- **需要给的量**：换 profile 对底价的影响（很小）。
- **只需要一句话的**：同一份库被多个进程映射、物理上只有一份。
  这是机制必然，读者也不会做出相反的决定。
- **现有实验**：`12-resident-memory.sh`。

### ④ 启动器要快 → 选「跟着一起起来的东西」少的实现

- **本来会怎么做**：挑一门「快」的语言。
- **为什么不行**：快慢不在语言，在**每次启动都要跨过去的那些东西** ——
  动态链接器每次都要找库、映射、重定位、调 init。
- **该怎么做**：选启动时没有额外东西跟着起来的实现（静态链接、无运行时）。
- **撑住它的事实**：
  1. 动态链接器每次启动做的四件事（`LD_DEBUG` 能打出来）
  2. 静态 vs 动态、有没有运行时的差值
  3. 跨系统调用边界有价格，数量级上比函数调用贵得多（**靶子，现在缺**）
- **需要给的量**：同一份源码两种链接方式的差；九种实现的最小延迟。
  口径必须写清（绑核取最小值 / 不绑核取 p50，两者不能混）。
- **现有实验**：`07-elf-loading.sh`、`08-dynamic-loader.sh`、`latency.sh`、
  `measure.sh`、`launchers/`。

### ⑤ 收束：四件事各自只做一次

把前四个决定合起来的那句总结（保温恒定的开销 / 生命周期交给管它的东西 /
能重做的回磁盘 / 热路径选跨边界少的）。它不引入新决定，所以只需要一句话。

## 三、分类规则

写一段内容时，先给它分类：

| 类 | 特征 | 怎么处理 |
| --- | --- | --- |
| **决定依据** | 不懂它就会做出不同的决定 | 必须给量或给实验，且要能落成决定 |
| **前提事实** | 决定本身能理解，但机制依据是断言的 | 用最小脚本量一次（十行量级，不需要漂亮） |
| **词汇** | 后面每句话都要用它，但读者不会因此改变做法 | 一句话讲清，不占实验位 |
| **装饰** | 不改变任何决定 | 删，或者降级成一句话 |

一个反面用法要专门避免：**用「你以为是 X 吧？」制造惊喜**。
那不是教学，是猜谜；而且会把篇幅花在读者不关心的事情上，
把真正要做的决定挤掉 —— 比如用半章讲「常驻成本比我印象里小」，
而读者真正需要知道的是「判据是可分离性，成本只是个阈值」。
每段内容都要能落到「于是决定怎么做」，落不到就属于装饰那一类。
（这条是这一版结构的由来：初稿按「读者会不会猜错」组织，
结果五个决定点被一堆数字盖住了。）

## 四、语言纪律

- 写**决定**，不写悬念：「于是要做一个决定：X 还是 Y」，
  然后给判据和数字。不要写「你猜这一秒花在哪」—— 读者不需要被考。
- **作者自己的故事要克制**：量错数字、用错工具这类经历，价值在方法论示范
  （「你自己量的时候会踩什么」），不在叙事。集中放一两处就够。
- **会动的数只给量级，精确值留在实验输出里**；不变的数（件数、口径、比例）
  正文和实验必须逐字一致。这条有测试钉着，见 `src/lib/courseware.test.ts`。
- 口径不同的两个数不能挨着放：写清楚哪个绑核、哪个取最小、哪个取 p50。

## 五、复检清单

新增或改写一段内容之后，逐条过：

1. 它服务五个决定点里的哪一个？（答不上来就别写）
2. 读者不知道它，会做出**不同**的工程决定吗？不会 → 压成一句话或删掉。
3. 它引的数是**会动的**吗？会动的话，正文里给的是量级还是某一个读数？
4. 它有没有依赖一个**现在还没有的前提事实**？有 → 先补前提（见下）。
5. 有没有「你以为是 X 吧」的句式？（要改成「于是要做一个决定」）
6. 贴进正文的实验输出，旁边有没有交底「它每次跑都会动」？

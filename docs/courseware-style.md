# 这门课的写作规范

这份文档记的是第一章反复返工之后收敛下来的标准。接下来四章按它改。

它分成三部分：**讲义**怎么写、**实验脚本**怎么写、**章**怎么写。每条都配了第一章里的正反例 —— 那些例子都是真的返工记录，不是编的。

---

## 零、三条底线

其余所有规则都是从这三条推出来的。判断不了的时候回到这里。

**一、数字必须跑出来，不能抄。**

课程对读者承诺：「每一章里贴的输出，都是这些脚本真跑出来的，不是手抄的。」一旦某个数字找不到产出它的脚本，它就是一个假证据 —— 哪怕这个数字是对的。

第一章抓到过两处：讲义上的「224 µs / 505 µs」是早先手工测的，没有任何脚本产出（后来补进 `07-elf-loading.sh`，实测是 357/513）；还有一处更隐蔽，见下面「先看到现象，再给框架」那节。

**二、结论是最不值钱的部分。**

数字和实现会被更好的工具重做一遍。「为什么问这个问题、当时期待看到什么、被什么打脸、于是怎么改假设」不会。所以：

- 讲义的职责是**提出问题**，不是给答案
- 实验的职责是**让人自己看见**，不是打印一份报表
- 章才负责把结论沉淀下来

**三、用自己脑子里的模型代替观测，是这门课反复出现的失误。**

引言里已经写过这句话。规范上也一样：每次写完一页/一个脚本，问的是「读者照着做一遍，会看见什么」，而不是「我讲清楚了没有」。

## 一、讲义

讲义是**现场用的**。它的读者是坐在下面的人，一页只有几十秒。

### 1.1 标题是关于主题的断言

标题要说这一页**主张什么**，不是这一页在讲什么话题。

```
✗  「启动」是什么意思
✗  回到开头：按下回车时 shell 做的就是这两步
✗  一个进程的地址空间长什么样
✓  新进程的创建分为两步
✓  qutebrowser 启动时做的就是这两步
✓  一个进程的地址空间，是一列区间
```

也别把标题写成关于这次演讲的元评论（「接下来我们看」「小结一下」）。

**标题可以带结论。** 正式内容里的数字不进讲义，但标题作为断言可以带 —— 「映射 1 GiB，物理内存只涨了 0.2 MiB」是允许的。要删的是**贴出来的结果块**，不是结论本身。

### 1.2 一页只放一个点

判断标准：这一页读完，读者脑子里多了一个什么？说不出来的，就是没有点 —— 删掉或者并到别页。

第一章删掉 8 页，全是这个原因：

| 页 | 为什么删 |
| --- | --- |
| 新进程的创建被分为两步是刻意的工程设计 | 整页在讲 shell 重定向和管道，跟「启动花多少时间」这条线无关 |
| 表和地址空间能一行行对上 | 4 行对 5 行的验证细节。结论（照表登记）上一页已经给了 |
| 为什么地址需要「修正」 | 四件事里一件的展开。读者不懂重定位照样看得懂账单 |
| 你的 main 不是第一个跑的东西 | 同上，初始化顺序的展开 |
| 一个进程的地址空间，是一列区间 | 整页 maps 输出，压成上一页末尾一句话 |

删掉不是丢掉 —— 这些内容都还在脚本里，谁想看谁跑。

### 1.3 结果不放讲义

跑出来的数字、原始输出、结果表，**都不贴在讲义上**。讲义上留一个指针：

```typst
#note[现场跑：`./docs/labs/resident-browser/05-mmap-not-occupied.sh`]
```

理由：讲课的时候应该**当场跑**给观众看。贴在讲义上等于把实验剧透了，而且观众会去读数字而不是看现象。

**唯一的例外是概念性的表** —— 它不是跑出来的，是在解释一种结构。这些留着：

```
✓ PT_LOAD / PT_INTERP 的释义表
✓ 「三种字节」该放哪（活的 / 死的缓存 / 页面状态）
✓ Wayland 和 D-Bus 的对照
✗ 「六种实现 × 五次重复」的性能表 —— 这是跑出来的，删
```

**删块之后要检查断头句。** 删掉一个输出块，前面那句「下面就是结果：」就悬空了。第一章删完 25 个块，留下三处这种断头句，都是逐页读出来的：

```
✗  办法是在那张表里加一项：          （后面没东西了）
✗  给全程打时间戳，找可以外部观测的界标：
✗  第二行那 2 GiB 是库被读进来了      （行都不存在了）
```

### 1.4 术语第一次出现的地方要有交代

第一章出过一次：某页标题是「一个编号指向什么，有三种情况」，但「编号」这个词前文从没出现过 —— 因为前一页改写的时候把它删了。

规则：**一个词在被当作主语使用之前，必须先有一次介绍。** 改一页的时候，顺手检查它介绍的词有没有被后面的页依赖。

### 1.5 先给读者一个可以拆的东西

拆掉一个概念之前，先让读者承认它。

讲虚拟内存那页，第一版是：

```
✗  但地址空间里装的不是内存，是地址 —— 而地址只是一串编号。
```

读者还没有「连续」这个概念，等于空拆。改成：

```
✓  从进程的视角看，这是*一整片连续*的地址：从 0 一直增长到极大的数字，
   数组里的元素一个挨着一个，指针加上偏移量就表示连续内存中具体的位置。
```

先建立「连续」，再拆掉它。

### 1.6 别把机制讲成结论

第一版把「进程创建分为两步」直接写成机制说明，读者的疑问（为什么不一步到位）没被回答。后来在标题里点明这是**刻意的工程设计**，正文才给出理由。

**能说「这是设计出来的」就别说「事情是这样的」。** 但理由本身可以选择不展开 —— 「为什么这么设计，先不展开」是允许的，只要读者知道它不是凑巧。

### 1.7 说人话，别造悬念

要删掉的几类句子：

```
✗  这才是陷阱                        （主观评价）
✗  第二条我踩进去了                   （个人叙事）
✗  最无聊的程序，最值得测              （主观评价）
✗  稳了                              （口语化断言）
```

替换方式：给一个**事实**说明它为什么值得注意，而不是给一个形容词。

```
✓  现存所有的 Unix 及类 Unix 操作系统内核（Linux、macOS、BSD、Plan 9 …），
   都用相同的方式创建进程。
```

**别造假精确。** 「几十次」就写「几十次」，不要写「二十次」。

**提问要是读者真正会问的。** 「该从哪里入手呢？」是读者的问题；「让我们看看它的内部结构」不是。

### 1.8 讲义形态

- 演示模式：一页 = 一屏，用键盘翻
- 版式语汇在 `.course.typ`：`title` / `slide` / `note` / `punch` / `cols` / `ask` / `lab` / `oops`
- 行内强调用**单星号** `*这样*`；多星号 `**` 是 markdown 习惯，仓库里的 lint 会抓
- 标题用 `=`，不要 `##`

### 1.9 一章讲义的分量

第一章改完的形状：

```
背景 10 页  /  正题 10 页
```

改之前是 17 : 10。背景介绍到「够读懂后面的实验」为止，不往下钻。

## 二、实验脚本

一个实验一个 `.sh`。**不许把一章的实验塞进一个脚本。**

### 2.1 四块结构

跑出来的输出就这四块，总共不超过 20 行：

```
  这个实验要回答：……

  <挑过的原始输出，每个数字带列名>

  <一句结论> + 用在哪（接回主线）

  （可选的观察入口：pid + 查看命令）
```

真样例（`05-mmap-not-occupied.sh`）：

```
  这个实验要回答：映射一个 1 GiB 的文件，物理内存会跟着涨吗？

  同一个进程的三个时刻：
  起点            地址空间       3.1 MiB    物理内存       1.8 MiB
  mmap 1024 MiB   地址空间    1027.1 MiB    物理内存       1.9 MiB
  读过 256 MiB    地址空间    1027.1 MiB    物理内存     257.9 MiB

  映射只是登记「这段地址的内容，去磁盘上那个文件取」—— 不读文件，也不分配内存。
  碰到才读，碰多少页涨多少页。

  内核装载可执行文件用的就是这套动作。「execve 把文件搬进内存」是错的：它没有搬。

  （进程停在 pid 228765，想自己看：grep -E 'VmSize|VmRSS' /proc/228765/status）
```

### 2.2 目的必须写在输出里

**读者打开脚本跑一下，第一眼就要知道这个实验是干嘛的。** 不能指望他去读课件。

开头一句话说清三件事（写成连贯的句子，不要列条目）：

1. 上一节留下了什么问题
2. 这个实验回答它的哪一部分
3. 这个答案接下来用在哪

`08-dynamic-loader.sh` 的写法：

```
  07 量到一件事：同一个程序，动态链接比静态链接要多花一百多微秒。
  这个实验要问的是：*那一百多微秒，具体花在哪几件事上？*

  为什么要问这个 —— 因为接下来整门课都在打同一个主意：
  把「每次启动都重做一遍、而且每次结果都一样」的那部分开销省掉。
```

反例：第一版 08 通篇在讲「链接器干了四件事」，读者跑完不知道要不要关心它。

### 2.3 形态要匹配内容

| 这个实验要回答什么 | 用什么形态 |
| --- | --- |
| **看现象** —— 内存、进程、状态 | 引导读者去 btop / ps / `/proc/<pid>` 自己看；留下活进程和 pid |
| **量数** —— 开销、计数、占比 | 跑一遍，出**一张表**，文字压到两三行 |

第一章犯过两次对称的错：把「量数」的 08 写成了引导式（四节各摆一屏原始输出），又把「看现象」的 05 写成了一屏报表。两边都难读。

### 2.4 不要「先猜」那类引导

```
✗  先猜一下：这一步会发生什么？
✗  想好了按回车
✗  pause "记住这两个数，按回车走下一步"
```

**内容做得足够简洁，答案自己就浮出来了**，不需要仪式。真正需要读者看的（活着的进程），在最后留一行入口：

```
  （进程停在 pid 228765，想自己看：grep -E 'VmSize|VmRSS' /proc/228765/status）
```

### 2.5 原始输出默认就要出

不许只给一张汇总表 —— 那样读者没法判断数字是算出来的还是手抄的。**先摆原始输出，再给表。**

```
  $ LD_DEBUG=statistics ./ctor-demo
    total startup time in dynamic loader: 103706 cycles
    time needed for relocation:            3250 cycles (3.1%)
    time needed to load objects:          38266 cycles (36.8%)

  四件事各自的账：
    找库             libctor.so 试了 3 个地方才轮到
    重定位           101 处，占链接器时间的 3.1%
    映射各 .so       占链接器时间的 36.8%
```

原始输出可以是**挑过的** —— 只留支撑结论的那几行。但挑出来的行不能改一个字。

### 2.6 每个数字旁边要有标签

读者不该去猜列名，更不该做心算。

```
✗  4927
✓  所有进程的地址空间加起来               4927 GiB   ← 读得到的 117 个进程，VmSize 求和
✓  地址空间是物理内存的                    328 倍    ← 上面两个数相除
```

### 2.7 注释里必须留的东西

脚本的注释不是写给读者看的，是写给**下一个改它的人**看的。必须留三类：

**一、不做就什么都看不出来的细节。** 这类最值钱：

```bash
# 库必须放在真实磁盘上，不能放 /tmp —— 本机 /tmp 是 tmpfs，
# 文件本身就是内存，从建出来那一刻就占着 RAM。放在那儿的话，
# 「读一遍」不会让内存有任何变化，实验就废了。
```

```bash
# 刚写完的库整份都还在页缓存里。不赶走它，「读一遍」这个动作在监视器上
# 就不会有任何变化 —— 读者会以为实验坏了。sync 先把脏页落盘，再 fadvise DONTNEED。
```

**二、写这个检查时撞出来的坑：**

```bash
#   1. 权限列 "R E" 中间有空格，不能只取一个字段
#   2. PT_LOAD 的地址不必页对齐，而内核映射时一定按页对齐 —— 比较前要向下取整
#   3. PIE 程序段表里的地址是相对基址的 —— 得先从 maps 里把基址反算出来
```

**三、会让结果静默变错的陷阱：**

```bash
# payload 必须放进脚本文件，不能用 sh -c '<payload>'。
# systemd 会对 ExecStart 做 $ 展开，而 $$ 在那里是「转义成字面美元符」的意思 ——
# 于是 echo $$ 到了进程里变成 echo $，主进程 pid 根本拿不到，
# 两档会静默地什么都没杀，实验看起来「通过」了其实完全无效。
```

### 2.8 三条工程纪律

- **跑完不留残留**：进程、scope、临时目录都要收干净。用 `trap ... EXIT INT TERM`，kill 的时候注意 `fork` 出来的孙子也要跟着死（`prctl(PR_SET_PDEATHSIG, SIGTERM)`）。
- **非交互也能跑**：`./xx.sh < /dev/null` 要能走完并返回 0。需要等待的地方判断 `[ -t 0 ]`。
- **不许用 `sort | head`**：`head` 读满就走，`sort` 会吃 SIGPIPE，在 `set -o pipefail` 下变成脚本失败，而且是偶发的。用 `sed -n '1,3p'`。

### 2.9 脚本编号

编号跟课件里的「演示 NN」对齐。`README.md` 里有一张表，把脚本、对应章节、干什么列出来 —— 改脚本的时候顺手改表。

## 三、章

章是**书面记录**，不是讲义的逐字稿。两者切法不同：

| | 讲义 | 章 |
| --- | --- | --- |
| 结果 | 不放，留指针 | 放。这是可核对的记录 |
| 节奏 | 一页一点 | 可以有推导过程 |
| 实验 | `#note[现场跑：…]` | `#lab(...)` 块，贴真实输出 |

**每个实验块下面带脚本路径**，用仓库根出发的写法：

```typst
#lab("演示 05：映射 1 GiB，物理内存一点没涨")[
  …
  （完整脚本：`./docs/labs/resident-browser/05-mmap-not-occupied.sh`）
]
```

**「演示 NN」的编号就是脚本编号。** 这样读者看到「演示 05」就知道去跑 `05-*.sh`。

章可以比讲义细，但**不能变成另一份讲义** —— 判断标准：这段文字是在陈述事实，还是在替读者思考？后者删。

## 四、技术约束

改 typst 之前必须知道这些，否则会白费功夫。

**HTML 导出会丢弃二维摆放原语。** `grid` / `place` / `columns` / `rect` / `line` / `stack` / `align` / `v` 全部被忽略并报警告。所以排版不能写在 typst 里。

分工是：**typst 说「这是什么」，CSS 说「它长什么样、放在哪」。** `.course.typ` 负责前一半（用 `html.elem` 交出带 class 的 HTML），`DocumentView.svelte` 负责后一半。

**HTML 导出没有「页」的概念。** `#set page(...)` 和 `#pagebreak()` 都是摆放原语，会被丢弃。讲义的分页靠 CSS 的 `scroll-snap`，每张 `c-slide` 撑满一屏。要真分页只能打印。

**lint 会扫 `content/` 下每一份 `.typ`：**

- 禁用上面那 8 个摆放原语
- 禁 markdown 习惯：`**加粗**`、行首 `##`、行首 `>`、markdown 表格 `|`
- 代码块和注释跳过

写完跑一遍 `typst compile --features html --format html --root . <file> /dev/null`，除了「html export is under active development」那一句，不该有别的 warning。

## 六、第一章的返工记录

留个账，改后面四章时对照。

**讲义**：28 页 → 20 页；背景 17 页 → 10 页。删掉 25 个结果块，全换成「现场跑」指针。

**实验**：一个 `01-process-creation.sh`（474 行，塞了 5 个实验）拆成 `01-fork` / `02-execve` / `03-redirect` / `04-address-space` / `05-mmap-not-occupied` / `06-one-copy`，后面的脚本顺延编号。输出从最多 206 行压到 9–25 行。

**章**：背景 408 行 → 344 行。

**补上的缺口**：`07-elf-loading.sh` 补了静态 vs 动态的启动开销测量（原来讲义上的 224/505 µs 是手抄的）；`13-qutebrowser-checkup.sh` 补回了被改掉的「把 1.2 秒切成几段」。

**顺手修的真 bug**：

- `01-fork.sh` 的 `fork` 出来的孩子不跟着父进程死 → 输出管道永远不关闭，脚本挂死。加 `PR_SET_PDEATHSIG`。
- `overflow-check.sh` 第 39 行 `unshare … bash -c '` 那个单引号把**整个脚本正文**包在里面，尾部的收尾引号被删过一次，脚本直接跑不起来。
- `07-elf-loading.sh` 的报告读的是中间步骤留下的 `dyn.maps`，改成断言阶段的 `hello-dyn.maps`，否则数字全空。
- `13-qutebrowser-checkup.sh` 体检二的 `--version` 会漏下 QtWebEngine zygote（原脚本就有，实测残留 4 个）。

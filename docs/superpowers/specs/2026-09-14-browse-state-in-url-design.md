# 浏览位置：把「上次看到哪」写进 URL

> 现在每次刷新都回到 `readme.md`。读一份长课件读到一半刷新，就得在树里重新点回去。
> 这份规格解决这一件事：**右栏打开哪篇、左栏展开哪些目录，写进 URL，刷新即恢复。**
>
> 选 URL 而不是 localStorage 的理由只有一条，但它是决定性的：**服务端读得到**。
> 正文本来就随 SSR 载荷整体内联，所以 `load` 拿到 `?file=` 之后，刷新出来的第一帧
> 就是那篇文章 —— 不存在「先渲染默认文档、等 JS 挂载之后再跳过去」的那一闪。

## 背景

`+page.svelte` 今天的浏览状态全在组件内存里：

| 状态 | 现状 | 刷新后 |
| --- | --- | --- |
| 右栏打开哪篇 | `chosenPath`，没点过就是 `data.initialPath` | 回到默认文档 |
| 左栏展开哪些目录 | `expandedPaths`（`SvelteSet`） | 全部折叠 |
| 光标停在哪一行 | `cursorPath` | 无光标 |
| 左栏开合 | `sidebarOpen` | 宽屏展开、窄屏收起 |

刷新是一次全新的 SSR 请求，上面四个全部归零。本次要修的是前两行。

## 目标

1. 刷新之后，右栏还是上次那篇文章
2. 刷新之后，左栏自动展开到能看见那篇文章的位置
3. 第一帧就是对的 —— 不能先闪一下默认文档
4. 内容改名、删掉之后，旧链接不能把首屏搞坏

## 非目标

- **不恢复滚动位置。** 切文档时恢复错位置比不恢复更烦人，另开一份规格再说
- **不恢复左栏开合。** 窄屏下树是浮层，默认收起是经过考虑的规则，不该被上次的状态推翻
- **不恢复光标。** 现有的 `moveCursor` 已有「还没有光标时，第一次按方向键就落到正在看的那篇」，
  正好接得上；刷新后不给任何一行画高亮，首屏观感与今天一致
- 不改文件树、正文渲染、演示模式的任何行为

## 已敲定的决策

| # | 决策 | 结论 |
| --- | --- | --- |
| A | 状态存哪 | **URL 查询参数**。可收藏、可分享、刷新即恢复，且服务端预渲染得到 |
| B | 参数名 | `file`（要打开的文档）、`dirs`（额外展开的目录） |
| C | `dirs` 编码 | **重复参数** `dirs=a&dirs=b`，不用逗号分隔 —— 目录名里可能有逗号，重复参数不需要转义 |
| D | 祖先目录 | **只补不写**：`dirs` 里不记当前文件的祖先（能从 `file` 推出来），读取时再补回去 |
| E | 打开文件 | `pushState` —— 「去了一个地方」，后退回上一篇 |
| F | 开合目录 | `replaceState` —— 视图偏好，不该往历史里塞记录 |
| G | 写入方式 | **原生 History API**，不用 `$app/navigation` 的 `pushState`（理由见下） |
| H | 校验时机 | **读取时一律按树校验**：`file` 必须存在且是文件，`dirs` 必须存在且是目录，其余丢弃 |
| I | 无效 `file` | 退回默认文档 `readme.md`，不报错 |
| J | 地址栏规范化 | 挂载时把地址栏 `replaceState` 成当前状态的规范编码，清掉失效参数、重复项、参数顺序 |

## URL 的形状

```
/?file=blog/why-yazi.md                  ← 常见情况就这么短
/?file=hacks/resident-browser/index.typ&dirs=projects
```

`dirs` 记的是**除当前文件祖先之外**的展开目录。展开集合 = `dirs` ∪ `file` 的祖先。
于是「只开着一个文件夹」这种最常见的情形不会在 URL 里重复一遍路径。

什么都没有时（根路径、没打开任何东西）URL 就是一个干净的 `/`。

## 读取规则

服务端 `load({ url })` 走三步：

1. `parseBrowseState(url.search)` —— 纯解析。空串、重复的 `dirs`、空值一律消化掉
2. `resolveBrowseState(tree, state)` —— 按树校验：`file` 不是树里的**文件**就归 `null`
   （指向目录也算无效）；`dirs` 里不是**目录**的丢掉；最后补上 `file` 的祖先
3. `initialPath = resolved.file ?? 默认文档`（默认文档同样要按树校验，沿用今天的
   `findFileTreeEntry` 那一次递归查找）

解析不认识的东西**不抛错、不警告**：URL 是外部输入，可能是几个月前的书签、可能是别人
手改过的。坏链接的正确表现是「打开首页」，不是「打开错误页」。

## 写入规则

| 动作 | 方法 | 理由 |
| --- | --- | --- |
| 点开一个文件 | `history.pushState` | 后退键回到上一篇 —— 这是浏览器的常识，不该在文件树里失效 |
| 开合一个目录 | `history.replaceState` | 展开文件夹不是「去了一个地方」。否则点开五个文件夹再想后退回上一篇文章，得按七次 |

客户端另有一个 `popstate` 监听：**直接读 `location.search`**，解析 → 校验 → 覆盖
`urlFile` 与 `expandedPaths`。这样后退/前进就跟点击走的是同一套读取逻辑。

挂载时还会做一次地址栏规范化（决策 J），所以用户不会停留在
`/?file=已删除.md&dirs=不存在&dirs=不存在` 这种地址上。

## 两个藏起来的坑

### 一、为什么不用 SvelteKit 的 `pushState` / `page.state`

翻过 `@sveltejs/kit` 2.70.3 的客户端源码，两条都不能用：

1. 官方文档在 shallow routing 的 Caveats 里明说：**刷新后 `page.state` 不会被应用**。
   它要解决的是「模态框能被后退键关掉」，不是「关掉标签页再回来还在原处」
2. `push_state()` 只写 `history.state`，**不更新 `page.url`**。而我们要的恰恰是地址栏本身

所以这里用原生 History API 改地址栏，把它当成那份持久化存储。SvelteKit 的路由器对我们
插入的记录（没有它的 `HISTORY_INDEX` 记账）会走 `popstate` 的兜底分支，只更新一下
`page.url`，不会重新跑 `load` —— 也就不会为了切一篇文章重传整棵内容树（正文是整体内联的，
重传一次就是整站的内容）。这一条是从 2.70.3 的 `client.js` 里读出来的，实现时按实测再确认。

### 二、已知例外：把当前文档所在的文件夹收起来

因为祖先只在读取时补（决策 D），下面这个状态刷新后会变：

> 正打开 `blog/why-yazi.md`，然后手动收起 `blog` 文件夹 —— 那一刻右栏那篇文档在左栏里看不见了。

刷新之后 `blog` 会重新展开，文档重新可见。

接受这个偏差，是因为反过来（把祖先也写进 URL）只能换来一个「文档在树里隐身」的自洽状态，
代价是每次都要在 URL 里重复一遍路径。而这个状态本身就不自洽 —— 用户会收起它，多半只是
手滑。

## 落点

| 文件 | 改动 |
| --- | --- |
| `src/lib/browse-state.ts` | **新增**。全部是纯函数：`parseBrowseState` / `browseStateOf` / `browseStateToSearch` / `resolveBrowseState` / `directoryAncestors` |
| `src/lib/browse-state.test.ts` | **新增**。解析、编码、校验、祖先、往返稳定性 |
| `src/routes/+page.server.ts` | `load` 接 `{ url }`，读 URL → 校验 → 返回 `defaultPath` / `restoredFile` / `initialExpanded`。逻辑都在纯模块里，这里只剩几行 |
| `src/routes/+page.svelte` | 播种展开集合；点击时写地址栏；`popstate` 同步；挂载时规范化地址栏 |

`chosenPath` 这个名字会消失，换成 `urlFile` —— 真相来源从组件内存搬到了 URL，名字得
跟着说实话：`openPath = urlFile ?? data.defaultPath`。服务端返回两个字段而不是合成一个
`initialPath`，是因为「地址栏什么都没说」和「地址栏指名了一篇但已失效」在客户端要区分开：
前者回落默认文档，后者同样回落——但只有分开表达，`popstate` 回到一个不带 `file` 的历史
记录时，行为才和直接访问那个地址完全一致。

## 测试

`browse-state.ts` 是纯函数，用 vitest 覆盖（沿用 `src/**/*.test.ts` 的既有约定）：

- 解析：空 search；正常 `file` + 多个 `dirs`；重复 `dirs` 去重；空值丢弃
- 编码：空状态 → `''`；`dirs` 有序且稳定；已有前导 `?`
- 校验：`file` 不存在 / 指向目录 → `null`；`dirs` 里混入文件路径 → 丢掉
- 祖先：顶层文件 → `[]`；`a/b/c.md` → `['a', 'a/b']`
- 往返：`parse(toSearch(state))` 与 `resolve(tree, state)` 在合法输入上稳定

服务端与组件不做单测（仓库现状：组件靠手点）。但**首屏这一点可以不用浏览器验证** ——
内容内联在 SSR 载荷里，`curl 'http://localhost:5173/?file=…'` 出来的 HTML 里是不是那篇
文章的正文，直接就能看。

## 修订（2026-09-14，实现并端到端验证之后）

写规格时只能从 `@sveltejs/kit` 源码里读出来的判断，实现后都实测确认了：

1. **点击不重跑 `load`。** 用 CDP 的 Network 域盯着点开 `blog/why-yazi.md` 的全过程：
   地址栏变成 `?file=blog/why-yazi.md`，而这期间**一个数据请求都没有**。所以切一篇文章
   不会重编译全站 typst、也不会重传整棵内容树。
2. **后退落在哪条记录上。** 开合目录走 `replaceState`，改写的是**当前那条**历史记录的
   URL。于是「先展开 blog → 点开 why-yazi.md → 后退」落到的不是干净的 `/`，而是
   `?dirs=blog`，也就是「blog 展开着、没指名文件」这个状态。这正是应该的：退回去的是
   那个状态，刷新它就该重现那个状态。

端到端一共 27 项检查（真 Chromium、真点击、真刷新），覆盖首屏、点目录、点文件、刷新、
后退、前进、失效参数、重复参数、分享深链接，控制台无报错。规格里那句「刷新后还是上次
那篇」就是第 4 组那四项。
